# 記録の移し方

作業の終わりに、成果物（spec・research・plan）から残す内容を移すときに読む。要約は SKILL.md「記録の移し方」にある。

`.tmp/sessions/` の成果物は 7 日で消える。spec・research・plan は commit しない。残す価値のある節だけを恒久の文書へ移す。移さなかった内容は、消えた後は戻らない。

## 移す節と行き先

| 元       | 節                                                                        | 行き先                                                |
| -------- | ------------------------------------------------------------------------- | ----------------------------------------------------- |
| spec     | Key Decisions、Alternative Approaches の却下した案、Risks、提供しない体験 | ADR の Decision / Consequences                        |
| research | 決定の根拠になった計測と事実                                              | ADR の Context。100 行を超える場合は `docs/research/` |
| plan     | 計画から外れた点、実装中に分かったこと                                    | ADR の Consequences                                   |
| どれでも | 範囲の外として次に回した課題                                              | `docs/plans/` の持ち越した課題の一覧                  |
| どれでも | 上の行に当たらないが、決定の理由を読むのに要る内容                        | ADR の Context                                        |
| 移さない | Tasks、Files、テストケース、Reviewer Outputs、Approval、Scope             | 残さない                                              |

単層モードの `plan.md` は spec と plan を兼ねるので、spec の行と plan の行の両方を当てる。

ADR を書かない作業では、表の「ADR の…」を「commit の本文」と読み替える。ADR も commit の本文の慣習も持たないプロジェクトでは、そのプロジェクトの記録の慣習に従う。

## 最後のタスクの書き方

移す作業は、計画の最後のタスクにする。単層モードでは `plan.md` の、二層モードでは最後に実行する `plan-N.md` の最後のタスクである。移す先の文書は、その計画の Files に載せる。

そのタスクの commit の本文に、次の 2 つを書く。

- 原本（spec・research・plan）の `##` 見出しの一覧
- 表の 1〜5 行目のそれぞれについて、「移した先の文書と節」または「該当なし」

6 行目（移さない）は書かない。原本があるうちに行う。抜けに気づいて原本から拾い直せるのは、成果物が消えるまでの 7 日の間だけである。

## `docs/plans/` に置くもの

`docs/plans/` には、今後やりたいことだけを置く。作業中の成果物と、終わった作業の成果物は置かない。

- **持ち越した課題の一覧**（`<主題>-followups.md`）: 終わった作業が範囲の外に回した課題を並べる。片付いた項目は消し、空になったらファイルを消す。項目を消す commit の本文に、消した項目の名前を書く。
- **未着手の作業の出発点**（主題の名前だけのファイル。冒頭に「未着手」と書く）: 調査、未解決の設計判断、次のセッションの起動プロンプトなど。その作業が終わったら、上の表に従って節を移し、最後のタスクと同じ commit でファイルを消す。

## 作業ツリーに無い記録の指し方

過去の記録が作業ツリーに無いときは、そのまま実行できるコマンドをバッククォートで囲んで書く。

```
`git show <commit>:<path>`
```

`<commit>` は 10 桁以上の hash で、既定のブランチから辿れるものに限る。書く前に `git merge-base --is-ancestor <commit> <既定のブランチ>` の終了コード 0 で確かめる。ファイルを指せば内容が、ディレクトリを指せば配下の一覧が返る。
