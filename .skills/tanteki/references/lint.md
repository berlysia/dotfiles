# 検査コマンドの使い方

textlint を使い、日本語の表現や文書の形式を機械的に検査します。内容が正しいかどうかは、執筆者が別に確認します。

## コマンドを実行する

このスキルの `SKILL.md` があるディレクトリを「スキルルート」と呼びます。必要なパッケージはグローバル textlint のランタイムが入れており、スキルルートの `node_modules` はそれを指します。パッケージのインストールは不要です。`scripts/lint.mjs` を実行します。

`--type` は必須です。`design-doc`、`prd`、`adr`、`rfc`、`stock`、`flow`、`record` を指定できます。選び方は[文書分類](document-types.md#検査コマンドの指定値)を参照してください。最初の5種類では、参照用の文書に作業進捗が混ざっていないかも検査します。`flow` と `record` では、この検査を外します。

別のディレクトリから実行する場合は、スクリプトと入力ファイルを絶対パスで指定できます。次は設計書と進捗報告の検査例です。

```sh
node /absolute/path/to/tanteki/scripts/lint.mjs \
  --type design-doc /absolute/path/to/design.md
node /absolute/path/to/tanteki/scripts/lint.mjs \
  --type flow --format json /absolute/path/to/status.md
```

`--format` には、画面で読むための `pretty-error`（既定）か、機械処理用の `json` を指定できます。入力には1つ以上の Markdown ファイルを指定します。同じ種類なら、複数ファイルをまとめて検査できます。

未知のオプション、未対応の拡張子、存在しないファイルを指定するとエラーになります。検査によって入力ファイルが書き換わることはありません。

## 検査するルール

| ルール名 | 検査する内容 |
|---|---|
| `preset-japanese` | 助詞の重複や二重否定など、日本語の文法上の問題 |
| `stock-boundary` | 参照用の文書に混ざった作業進捗や追跡情報 |
| `table-cell-length` | 表の見出しと本文セルの文字数 |

`stock-boundary` は `stock` と同じ検査を行う文書に適用します。作業進捗、チェックボックス、PR番号、PR・Issue・Jira の URL が対象です。その他のルールは全区分に適用します。

名詞を重ねた分かりにくい名詞句（`opaque-compound`）と、程度や指示語だけで動作を述べる曖昧な表現（`vague-action`）は、この検査コマンドでは見ません。japanese-check の `check` が、形態素解析の結果から `findings` として候補を出します。

## 日本語の文型と検出範囲

文型の検査は japanese-check の `check` が持ちます。`適切に対応しました` のような曖昧な動作や、`業務の効率化の基盤` のような名詞の連なりは、`check` の `findings` に `vague-action`、`opaque-compound` として出ます。このコマンドは、助詞の重複や二重否定など、preset-japanese の検査だけを行います。

文脈に合う言葉かどうかは執筆者が判断します。検査で扱っていない表現や、離れた語同士の修飾関係、文脈に合う訳語かどうかも、執筆者が確認します。未知の問題を見つけたら、同じ構造の言い換えと、それに似た正しい用例をテストに加え、検出漏れと誤検出の両方を確認します。

## 表の文字数

`table-cell-length` は、表示上61文字以上のセルを指摘します。Markdown の装飾記号とリンク先URLは数えず、リンク表示文とインラインコードは数えます。セル前後の空白は数えません。結合文字と複数コードポイントの絵文字は、表示上の1文字として数えます。セル内で改行しても、セル全体で数えます。

引用原文とコード例はこのルールの対象外です。HTML や Markdown 以外の表にも同じ上限を適用し、執筆者が確認します。長い説明を表へ詰め込まず、表の外へ移してください。条件や例外を削ってはいけません。意味のない分割や独自の略語で文字数だけを減らしてもいけません。

## 終了コード

実行後の終了コードで、検査が完了したかを確認できます。

| 終了コード | 意味 |
|---|---|
| `0` | 検査が完了し、指摘がない |
| `1` | 検査が完了し、指摘がある |
| `2` | 引数・設定・ファイルの読み書きにエラーがある |

終了コード 1 で、stderr に `Cannot find package` か `ERR_MODULE_NOT_FOUND` があるときは、指摘ではなく依存が見つからない状態です。

検査が動かないときの扱いは、`SKILL.md` の「検査して届ける」に従います。

指摘された表現は、文の意味を確認してから直し、最終変更後に再検査してください。検査に通っても、辞書やパターンにない表現、文をまたぐ指示関係、事実の正しさは保証されません。日本語の意味は [日本語の基準](japanese.md)、節の分担と形は [文書の構成と本文の形](structure.md) に沿って確認します。一般の技術語を長さだけで禁止しません。直訳調の語の検出はこの検査コマンドの対象外で、japanese-check の `check` が持ちます。

## 残す表現の記録

検査の指摘を残す表現は、本文の該当行に japanese-check の keep の注記（rule 名、対象の文字列、理由を書く）で記録します。書き方は japanese-check の `check` の出力と SKILL を参照してください。このコマンドの検査に、例外を登録する設定はありません。表セルの上限も緩められません。検査を通すためにルール全体を無効にしたり、問題のある文をコードや引用へ移したりしてはいけません。
