# Plan: <feature/change name> (Execution layer)

> **Template usage**: 二層モードの実行層。1 spec から N plan を切り出し、各 plan-N.md を独立に承認・実装する。ファイル名は `plan-1.md` / `plan-2.md` …（連番、欠番可）。

## Files

実装で触るファイルを **fenced code block + 1 行 1 パス（プロジェクトルート相対）** で列挙する。`document-workflow-guard` はこの code block を `realpath` 完全一致でパースする。`#` 始まりの行と空行は無視、それ以外の非パス行（インデント・タブ混入・複数パス連結等）は形式違反として実装ブロック。

```
# 新規作成
src/feature/example.ts

# 編集
src/feature/existing.ts
docs/feature.md

# テスト
tests/feature/example.test.ts
```

## Tasks

plan に書くのは、実行するまで分からない決定だけにする。実行すれば分かること（コードの書き方、テストの書き方、コマンドの出力）は、実装者がテストを走らせて確かめる。

- **書く**: 振る舞いの契約（入出力、形式、終了コード、エラーの意味、空や上限の扱い、テストが依存する環境の前提）、不変条件（セキュリティ、並行性、データの保全。手段そのものが決定なら手段まで）、テストケース（入力 → 期待）、タスクの分割と順序、触るファイルと参照
- **書かない**: 実装コードとテストコードの本体、fixture の定義、実行コマンドと期待出力の逐語、コミットの手順、内部の関数分割と命名
- **例外**: コードが決定そのもののとき（公開する型やシグネチャ、ファイル形式のスキーマ、セキュリティ上の正確な式）はコードで書いてよい。ブロックの直前に「なぜコードで固定するか」を 1 行書く

レビュアーはこの境界で読む。契約・不変条件・テストケースの抜けは指摘の対象、plan 内のコードの細部は対象外。
