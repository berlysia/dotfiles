# ADR-0047: 日本語文書のゲートは、1 回の呼び出しの前後で変更を帰属させ、状態をホーム配下に置く

## Status

accepted (2026-10-23)

## Context

日本語文書のゲート（`japanese-document-gate`）は、人が読む日本語文書が最新の本文で検査済みかを、終了と公開の前に確かめるフックである。導入した直後の 2026-10-23 に、次の問題が見つかった。

- **他のセッションの変更を、自分の変更として追跡した。** ある session は文書を一度も編集していないのに、2 つの文書を `stale` として追跡した。19:09:06 に最初の Bash で、セッションの起点となる各文書のハッシュが記録された。その後、別のセッションがマージの準備として作業ツリーを前の commit の内容に戻したとみられる（直接は観察していない）。19:10:44 に、この session の Bash の後のフックが、起点と違う内容を見て追跡に加えた。19:10:46 に、別のセッションが fast-forward でマージした。フックが通知したハッシュは、前の commit の版の sha256 と一致した。原因は、Bash の変更を「セッションの最初の Bash の時点」と比べていたことである
- **状態の置き場が cwd で割れた。** 置き場は cwd から探した Git のルートの `.tmp/japanese-check/` だった。同じ session が worktree へ移ると、19:15 に 2 つ目の置き場ができ、移る前に追跡した文書は見えなくなった。CLI を別の cwd で実行したときも、記録は別の置き場に入った
- **同じ通知が、ツール呼び出しのたびに届いた。** 未検査の集合が変わらなくても、PostToolUse のたびに同じ一覧が文脈に入った
- **記録が 1 件壊れると、終了できなくなった。** 壊れた記録の読み込みは例外になり、check でも上書きできなかった。フックの例外は Stop を止めた
- **公開の判定が誤った。** コマンド文字列全体への正規表現で判定していたので、`echo "git commit"` や `gh api -F k=v` も公開や本文ファイルとして扱った

## Decision

- **K1: Bash の変更の帰属は、同じ呼び出しの PreToolUse と PostToolUse の差分で決める。** Pre で候補文書のハッシュをスナップショットに書き、Post で読んで比べ、読んだら消す。キーは `tool_use_id` のハッシュである。Claude Code と Codex 0.163.0 の両方で、Pre と Post に同じ `tool_use_id` が入ることを確かめた（Codex は一時的な `CODEX_HOME` に入力を書き出すフックを置いて実測した）。`tool_use_id` が無い呼び出しと、Pre・Post の列挙に失敗した呼び出しでは、帰属を省き、セッションで 1 回だけ知らせる
  - 却下: セッションの起点を Pre ごとに書き直すだけの案。比べる範囲が「前回の Bash から今回まで」に広がり、同じ誤追跡が残る
  - 却下: `tool_use_id` が無いときにセッションで 1 つの枠を使う案。並行する Bash の Pre が互いを上書きする
- **K2: 状態は `~/.claude/state/japanese-check/` に置く。** 記録の鍵は文書の実パスのハッシュなので、プロジェクトをまたいで共有しても衝突しない。使う前に、symlink でないこと、ディレクトリであること、所有者が自分であることを確かめる。mode だけが緩ければ 0700 に直す。既存の `.tmp/japanese-check/` の記録は移行しない
  - 却下: プロジェクトの中に置き続ける案。worktree で作業する決まりがあるので、cwd が変わるのは通常の使い方である
- **K3: Stop を止めるのは、検査が残っているときだけにする。** フック自身の故障では、どのイベントでも止めず、知らせだけを出す。壊れた記録はその文書の `stale` として扱い、check で上書きできる。壊れた追跡項目は消して知らせる
  - 却下: 故障の回数を数えて上限で通す案。新しい永続状態が増える
  - 却下: `stop_hook_active` だけを理由に通す案。ゲートの意味が無くなる
- **K4: 公開の判定は、`lib/command-words.ts` の分割で単純コマンドごとに行う。** 公開とするのは `git commit|push` と `gh pr|issue create|edit|comment` だけで、本文はそのコマンドのフラグの値から取る
- **K5: 未検査の通知は、集合が変わったときだけ出す。** 出力に載せるパスは `sanitizeForDisplay` で整形し、コマンド例のパスは引用符でくくる
- **K6: 古い状態は Stop のたびに掃除する。** 7 日使われていないセッション、1 時間を過ぎた孤児のスナップショットと一時ファイルを消す。検査記録は消さない
- **Document Workflow の成果物は、ゲートと CLAUDE.md の規則の両方から外す。** 利用者は workflow dir の文書を要点だけ拾って読むと明言した。作業の途中に Stop が何度も止まり、中身の無い `defer` を打つことが続いた。ゲートだけ外すと、規則に従って手で check し続けるので、規則にも同じ除外を書いた
  - 却下: 編集した文書を自動で草稿として扱う案。公開の扱いは変わらず、本文を直すたびに Stop も止まるので、状態の名前が変わるだけだった

## Consequences

- コードは `japanese-check/` の state・receipts・tracking と、`hooks/lib/japanese-document-gate/` の gate・discovery・publication・shared に分かれた。`japanese-check/` は hooks を import しない
- 配布の後は、検査器のハッシュと置き場が変わるので、既存の記録はすべて `stale` か `missing` になる。追跡中の文書は check をやり直す
- 限界は `.skills/ja-check/references/human-documents.md` に書いた。主なものは次のとおりである
  - 1 回のコマンドの実行中に他者が同じ文書を変えると、自分の変更として追跡する
  - ゲートは自己申告で、故障を起こせば通れる
  - `bash -c`、`eval`、スクリプトの中の公開と、workflow dir の下の本文ファイルは見ない
- 検査記録は消さないので、検査した文書の数だけ増える
- 観測していない Codex の挙動は [docs/plans/japanese-document-gate-followups.md](../plans/japanese-document-gate-followups.md) に残した
