# ADR-0046: スキルが読み込みを指示したスキルを、送る操作の前に 1 回確かめる

## Status

accepted (2026-10-23)

## Context

pr-description は「執筆前に `tanteki`・`japanese-tech-writing`・`koncise` の各 skill を読み込む」と指示している。2026-10-23、モデルは PR #369 と #370 の本文を書くときに pr-description を読み込んだが、3 つのスキルはどれも読み込まなかった。transcript の Skill の呼び出しは pr-description だけだった。

読まなかった理由は読み忘れではなく、モデルが「3 つ読むと文脈が重い。textlint で足りる」と判断して省いたことである。指示の文言を強めても、同じ判断でまた省きうる。

同じ形の指示は visual-eli にもある（ページを書く前に `stop-describing-ui` を読み込む。読めなければ無しで書いてよい）。入口のスキル（tanteki、japanese-tech-writing、yomiyasu）が役割スキル（ja-*）を Read で読む指示は、読めなければ作業を止めると各入口が決めており、仕組みが別である（ADR-0036）。

利用者の判断: 範囲は「指示するスキル全般」、強さは「送る前に 1 回止める」。

## Decision

### 宣言

- **K1: 宣言はスキル自身の frontmatter の 2 つの欄に置く。** `requires-skills` は先に読み込むスキルの名前の配列で、`requires-skills-before` は確かめる操作のパターンの配列である。パターンは `Bash(<コマンドの先頭の語の並び>)` と `Write(**/*.<拡張子>)` の 2 種類だけにする。照合は自前で持ち、`lib/pattern-matcher.ts` は使わない（permission の評価の重い依存を抱え込むため）
- **K2: 名前とパターンに制約を置く。** スキルの名前は `^[a-z0-9][a-z0-9._-]*$` で 64 字以内とし、`..` を含まないものだけを使う。`requires-skills` は 10 件まで、`requires-skills-before` は 5 件までで、各パターンは 80 字以内とする。`Bash(...)` の語の並びは 2 語以上にする。外れた宣言は捨てる。外部のスキルが `Bash(git)` のような広い宣言を書いても、止まる範囲はこの制約で限られる
- **K3: 宣言は配布されたスキル（`~/.claude/skills/*/SKILL.md`）から読む。** 各 SKILL.md は、symlink でない通常ファイルの先頭 8 KB だけを読む。frontmatter は YAML のライブラリを使わず、行単位で 2 つの欄だけを読む

### 判定

- **K4: 確かめるのは、操作が宣言のパターンに当たったときだけにする。** Bash は `prepareDenyInput` で分けた個々のコマンドを照合し、heredoc の本文には当たらない。Write は `file_path` の拡張子を照合する
- **K5: 「読み込まれた」は、transcript のスキルの読み込みのレコードだけで判定する。** 数えるのは `type: "user"` かつ `isMeta: true` で、最初の文の部分が「Base directory for this skill: 」で始まるレコードだけである。tool_result やモデルの文に同じ文字列があっても数えない。transcript は新しい側から 4 MB ずつ、最大 256 MB を読む。境界で割れた行は、バイト列のままつないでから処理する。要る名前が揃ったら読むのをやめ、1,500 ms を過ぎたら通す。宣言したスキル自身が読み込まれていなければ、確かめずに通す
- **K6: 止めるのは、セッションと宣言したスキルの組ごとに 1 回にする。** 印は deny するときだけ排他で作る（`lib/session-marker.ts`）。英語の PR のように指示の条件に当たらない場合や、スキルを読み込めない場合にも、作業が止まり続けないようにするためである
- **K7: deny の理由の文には、読み込まれていないスキルの名前と、次の 2 つを書く。** 「Skill ツールで読み込んでから同じ操作をやり直す」と、「条件に当たらない場合や読み込めない場合は、省く理由を応答に 1 行書いてからやり直せば通る」である。黙って省くことを、理由つきの判断に変えるためである
- **K8: 失敗しても止めない。** どの例外でも終了コード 0 で何も出さない。全体に 2 秒の watchdog を置き、settings の `"timeout": 5` を最後の網にする。subagent からの呼び出しは通す。`allow` と `ask` は返さない

### 記録と検査

- **K9: 判定を `~/.claude/state/skill-requires-gate/decisions.log` に記録する。** 記録するのは、deny、deny の後の初めての通過（その時点で読み込まれていないスキルの名前つき）、締め切りでの通過の 3 つで、どれも組ごとに 1 回である。締め切りの記録は、宣言したスキルの読み込みが見つかっていた場合だけにする。本文とコマンドは書かない
- **K10: 宣言の検査を unit test に置く。** hook は誤った宣言を黙って無視するので、検査が無いと宣言が効かないことに気づけない。検査は実行時と同じ読み取りの関数を使い、名前が `.skills/` か `apm.yml` にあることを確かめる

## ADR-0044 との関係

部品（deny の形、fail-open、watchdog、`lib/session-marker.ts`）は ADR-0044 の差し戻しと同じである。違うのは、止める単位と、印を消す時点である。ADR-0044 は 1 turn ごとに 1 回止め、利用者の入力で印を消す。この ADR は、セッションと宣言したスキルの組ごとに 1 回止め、入力では消さない。指示の条件に当たらない操作を、入力のたびに止めないためである。

## ADR-0036 との境界

役割スキルを Read で読む指示は、ADR-0036 のとおり各入口が受け持つ（読めなければ止める）。この ADR が扱うのは、スキルが Skill ツールでの読み込みを指示する場合だけである。

## 却下した代替案

- **pr-description の文言を強める。** 今回の失敗は判断による省略で、文言を強めても同じ判断で省きうる
- **pr-description 専用の hook にする。** 範囲は「指示するスキル全般」で、visual-eli も同じ形の指示を持つ。スキルを足すたびに hook を直すことになる
- **スキルを読み込んだ時点で、指示されたスキルを自動で読み込む（白紙設計案）。** 依存を宣言しておけば、読む側に判断を残さずに済むのが利点である。しかし hook から別のスキルを読み込ませる手段が無い（hook が返せるのは deny、allow、ask と文脈の文だけ）。PostToolUse(Skill) で知らせる案は止めないので、利用者が選んだ強さに当たらない

## 見直しの条件

`decisions.log` で、deny の後の通過のうち、読み込まれていないスキルが残ったままの割合が高ければ、deny が読み込みにつながっていない。この仕組みを外すか、強さを見直す。締め切りの記録の割合が高ければ、読み取りが遅くてゲートが働いていないので、transcript の読み方を見直す。

## Consequences

### Risks（受け入れたもの）

- deny の後に読み込まずにやり直せば通る。強制ではなく、省くなら理由を書かせるためのものである。モデルが応答に理由を書いたかは hook から見えないので、記録できない
- 宣言したスキル自身を読まずに送る経路は止めない。指示は、宣言したスキルを読み込んだときに生じるためである
- すり抜ける経路がある。`gh api` の PATCH、`gh -R x pr create` のように途中に option を挟む形、`env`・`command`・`sudo`・`bash -c` を前に置く形、別名や関数、Write を使わない HTML の作成、subagent からの呼び出しである。fail-open の hook なので、すり抜けても止まらないだけになる
- 英語の PR でも 1 回止まる。visual-eli を読んだセッションでは、関係の無い HTML の Write でも 1 回止まる
- 判定は、Claude Code が transcript に残すレコードの形に頼る。形が変わると判定が外れ、毎回 1 回止まる側に倒れる。fixture は実物から取ってあるので、取り直したときに気づける
- transcript の末尾 256 MB より前に読み込んだスキルは見えない。遅い I/O で毎回締め切りを過ぎると、ゲートは働かない（締め切りの記録で数えられる）
- 宣言は配布された `~/.claude/skills` から読むので、merge して apply するまで効かない
- hook は Bash と Write のたびに bun を起動する
