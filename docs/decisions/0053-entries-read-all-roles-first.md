# ADR-0053: 文章スキルの入口は、作業に入る前に `役割:` の行の役割をすべて読む

## Status

accepted (2026-10-27)

## Context

ADR-0036 は、日本語の文章スキルを、規則を持つ役割（`ja-*`）と、読者と目的を持つ 4 つの入口（koncise、tanteki、yomiyasu、japanese-tech-writing）に分けた。入口は冒頭の `役割:` の行で読む役割を宣言する。ADR-0052（ja-explain-first の役割）で試験をした。japanese-tech-writing を名前で呼び、原文なしで書かせると、`役割:` の行の役割を一つも読まなかった。ADR-0052 はこれを残る限界とし、`docs/plans/ja-skills-role-relations.md` に残件として書いた。

2026-10-27 に、配布済みのスキルで同じ条件の試験を流した。`claude -p --model sonnet --output-format stream-json` で、ツールは Read と Skill だけ、MCP は読み込ませず、判定は tool_use の Read の path で行った。

- japanese-tech-writing、原文なしで書く依頼: 3 回とも役割を 0 個読んだ。ADR-0052 の 2 回と合わせて 5 回中 5 回である。最終出力に「役割スキルは読んでいない」と書き、止まらずに本文を返した。宣言の 3 行目の「読めなければ、作業を止める」は守られていなかった
- japanese-tech-writing の推敲 2 回と tanteki 3 回: ja-structure と ja-paragraph は 5 回とも読まなかった
- 入口の本文を grep すると、読まれなかった役割は、`役割:` の行の外のどこからも指されていなかった。本文で指していない役割は、japanese-tech-writing と tanteki のどちらも ja-structure、ja-paragraph、ja-explain-first である

japanese-tech-writing は `.skills/` の自作で、上流から派生していない。ADR-0052 が「上流由来の入口の本文を動かす」と書いた理由は、この入口には当てはまらない。

## Decision

- **K1: 入口の宣言の 3 行目に、作業の前に役割をすべて読む指示を織り込む。** 「読めなければ、作業を止める」の前に、「作業に入る前に、上の役割スキルをすべて読む。新しく書くときも、書き直しや推敲のときも読む」の趣旨の 2 文を入れる。文面を決めるのは、今までどおり `.github/scripts/check-skill-refs.sh` の `C2_FACT_LINE` である。この ADR には文面を書かない。
- **K2: 4 入口すべてに入れる。** 定数が 1 つなので入口ごとに分けられない。koncise と yomiyasu も、本文で指さない ja-explain-first を `役割:` の行に持つ。`ENTRY_COND_ROLES` の役割は、koncise の ja-structure と ja-check、japanese-tech-writing の ja-check である。これらは `役割:` の行に無く、指示の「上の役割スキル」に含まれない。条件つきの読み方のまま変わらない。
- **K3: japanese-tech-writing の「原文も資料も無く自分で原稿を書くときの規則は、この文書が持つ」は変えない。** この文が決めるのは原文なしで書くときの事実の扱いの持ち主で、読むかどうかは 3 行目が決める。この文を残したまま、試験では全部読んだ。

この決定で、ADR-0036 の 2 か所を改める。

- 「入口の宣言」: 3 行目は、事実の規則とデータの扱いに加えて、役割をすべて読む指示を持つ
- 「残る限界」の「入口が役割を読むかは、モデル次第である」: 3 行目で読む指示を明示したので、読まないことは確率として残るが、本文の書き方による読み落としは減った

## 却下した代替案

- **japanese-tech-writing の上の 1 文だけを直す（差分最小）。** 原文なしの 0 個は直る見込みがあるが、推敲と tanteki で ja-structure と ja-paragraph を読まない問題は残る。
- **役割が要る場面の近くに、読む文を足す。** ADR-0036「役割の規則を、入口の横にも書く」と同じ形である。コピーの試験（下の Consequences）で、japanese-tech-writing では 6/6 で全部読んだが、tanteki では 0/3 だった。上流から派生した tanteki の本文に 3 か所足すことにもなる。回数が少ないので、この案では読まないとまでは言えない。
- **宣言の 3 行の後に、4 行目として読む指示を足す。** コピーの試験では K1 と同じく全部読んだ。3 行目が事実の規則とデータの扱いだけを持つ形は保てる。代わりに検査 (3) に定数と照合の規則を足し、テストの fixture を作り直し、ADR-0036 の「3 行」を 4 行に改めることになる。3 行目が二つの役目を持つ代償より、この費用のほうが大きいと判断した。
- **入口の SKILL.md を役割の本文と結合して生成する、または Skill の起動を hook で検知して役割を注入する（白紙設計）。** 読むことを機械で保証でき、確率が消える。ただし結合生成では、役割を 1 か所で持つ ADR-0036 の分け方と、`check-skill-refs.sh` の参照の検査を作り直すことになる。上流から派生した tanteki と yomiyasu の本文も生成物に変わる。hook の注入は、同じスキルを使う Codex では動かない。
- **「読んだと確かめられるまで本文を書かない」のような、より強い文にする。** K1 の文がコピーの試験で全部読ませたので、弱い側の文から採った。

## Consequences

### 試験の結果

配布先の `~/.claude/skills` は全セッションが共有するので、merge の前の試験は、cwd の `.claude/skills/` に入口のコピーを別名で作って行った。同名のコピーは配布済みのスキルが優先されて使われなかったため、名前を変えた（`jtw-*` など）。条件は Context と同じで、入口の呼び出しが試験する名前でない回は無効とした。

| 入口と依頼                      | 役割の数 | コピーの現状 | 場面の近くに読む文 | 4 行目   | K1 の文 | merge 前の最終ファイル |
| ------------------------------- | -------- | ------------ | ------------------ | -------- | ------- | ---------------------- |
| japanese-tech-writing、原文なし | 5        | 1/3          | 3/3                | 3/3      | 3/3     | 3/3                    |
| japanese-tech-writing、推敲     | 5        | 0/3          | 3/3                | 3/3      | 3/3     | 3/3                    |
| tanteki                         | 7        | 0/3          | 0/3                | 3/3      | 3/3     | 3/3                    |
| koncise                         | 2        | 試験なし     | 試験なし           | 試験なし | 2/2     | 2/2                    |
| yomiyasu                        | 6        | 試験なし     | 試験なし           | 試験なし | 2/2     | 2/2                    |

数字は、`役割:` の行の役割をすべて読んだ回の数である。依頼の文は、3 文の固定の文と、「承認と実行を分ける理由を 3 文で」の 2 つだけにした。

コピーの現状は、配布済みの本物より多く読んだ（原文なしで本物は 0 個、コピーは 3 回中 1 回が全部）。置き場か名前の違いで挙動が変わっており、コピーの結果は案どうしの比較にしか使えない。本物での結果は、配布の後に追記する。

### 残る限界

- 読むかどうかは、今もモデルの読みに頼る。回数は各 2〜3 回で、全回で読んでも、読まない確率が 0 になったとは言えない
- 判定は Read があったかだけで、読んだ役割の規則を出力に使ったかは確かめていない
- 読み忘れを検知する仕組みは作っていない。作るなら hook に頼り、Codex では動かない
- 検査 (3) は 3 行目の文の一致だけを確かめ、読んだかは確かめない
- `ENTRY_ROLES` と `ENTRY_COND_ROLES` が重ならないことは検査しない。今は重ならない。重なると、常に読む指示と条件つきの読み方が食い違う
- 本物で読まない回が出たときの次の手の候補は、4 行目に分ける案と、より強い文にする案である

### 読む量

各入口で、`役割:` の行の役割の Read が毎回そろう。tanteki は 7 ファイル、japanese-tech-writing は 5 ファイルになる。読み込み量の目安と、tanteki の超過を受け入れたことは ADR-0036 の「読み込み量」にある。常に読む範囲は ADR-0052（ja-explain-first の役割）の K2 で利用者が選んでいる。
