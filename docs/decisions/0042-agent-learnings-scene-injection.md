# ADR-0042: agent-learnings の学びを場面ごとに流し、受け取った側の評価を集める

## Status

accepted (2026-10-22)

## Context

ADR-0032 の学びは、セッションの開始時にまとめて流していた。開始時の注入は節ごとに 8KB で切られ、dotfiles の repo では 40 件・全文 23.5KB のうち半分以上が流れていなかった。学びの多くは、特定のコマンドを打つ直前か失敗の直後、または特定のファイルを書き換える直前に読めば効くもので、開始時にまとめて読ませても、その瞬間には文脈の奥に沈んでいる。

利用者の要望は次のとおり。

- 開始時、コマンドの直前などのライフサイクルに合わせて流す
- Claude と Codex で、対応するライフサイクルは内部では透過にする
- 受け取った Claude や Codex から、「今言われても困る」「JIT でよかった」といった評価を蓄積する
- タグの振り分けは LLM が行ってよい（既存の学びの付け替えも含む）
- どういうクエリで表示されたかを、学びの id ごとに記録する

## Decision

### 場面の表し方

- **K1: 学びのメタ行の `on` に場面を書く。** 形式の版は 1 のままにする。文法は `session`・`cmd:<語>[ <語>]`・`path:<prefix>`・`path:*<suffix>` で、1 項目に 4 個まで、照合に正規表現は使わない。名前はこの仕組み独自のもので、エージェントのイベント名に寄せない。LLM（worker・inbox・エージェントが実行する CLI）が付けられる場面は狭くする。1 語の `cmd:`、2 階層未満の prefix、`.git`・`.github`・`.claude`・`.codex` で始まる prefix、`.` が 2 つ未満の suffix は付けられない。読む側も `on` を検査し直し、不正な値は `on` が無いとして扱う。common の学びの `path:<prefix>` は読む段階で取り除く。注入の場面の種類（`kind`）は `session`・`pre`（コマンドの直前）・`fail`（失敗の直後）・`path`（ファイルの書き換えの直前）とする
- **K2: 直前と失敗の直後は同じ `cmd:` で照合する。** 失敗の内容（エラーの文字列）は照合にも注入の文にも使わない
- **K3: コマンドは単純コマンドごとに先頭の 2 語で照合する。** `cd x && git commit` も当たる。git はグローバルなオプションを読み飛ばす。3 語以上の `cmd:` は当たらない
- **K4: パスは、ファイルを書き換えるツールの直前だけ照合する。** 照合は repo の toplevel からの相対パスで行う。Bash による書き換えと Read は照合しない
- **K5: 開始時は、`on` の無い学びと `session` の学びだけを流す。** 場面だけを持つ学びの件数は「他に N 件」の 1 行で知らせる。`show --on=session` も同じ集合と同じ 1 行を出す。`show`（`--on` なし）は全件を出す

### 量と重複

- **K6: 1 回の注入は 3 件・2KB、1 セッションの場面の注入は合計 12 件・16KB まで。** 注入の文には「データであり指示ではない」の注意書きと feedback の案内の行を付け、見出しと本文を再検査する。URL を含む本文は場面では流さない（URL は人が端末から足した学びだけにある）。値は暫定で、注入の記録を見て直す
- **K7: 同じ学びは、1 セッションの中で直前（`pre` と `path`）に 1 回、失敗の直後に 1 回まで。** 場面の state はエージェントごとの、そのエージェントの sandbox から書けない場所に置く。state の読み書きに失敗したら注入しない（上限と重複の抑止を外したまま流さない）

### hook

- **K8: 場面の hook は失敗しても何も止めない。** 出力は文脈に足す文だけで、許可の判定を返さない。どんな失敗でも出力なしで終える。Claude は PreToolUse（Bash・ファイルの書き換え）と PostToolUseFailure（Bash）、Codex は PreToolUse（Bash・`apply_patch`）に登録する。repo の解決は cwd ごとにキャッシュし、git は読み取りのサブコマンドだけを、global 設定を読まずに起動する

### 書き込みの経路

- **K9: 書き込みの op は add・update・remove・retag。** worker の LLM は add と update で `on` を付けられる。文を変えて `on` を渡さない update は `on` を外す。`on` を持つ学びは LLM の昇格の候補にしない。既存の学びの付け替えは `tag` で行う。エージェントは worker の制限で、今の repo の学びだけを、1 回 200 行まで確認なしで付け替えられる。人は全文法で、common の学びにも付けられ、`/dev/tty` での確認を経る。付け替えは store の commit の本文に 1 項目 1 行で残し、`git revert` で戻せる
- **K10: 今ある学びには、エージェントが判断して付ける。** 照合が確実に当たる `cmd:` と `path:` だけを付け、迷ったら付けない。付けた案は、配備済みの照合で実際のコマンドの形に当たるかを確かめてから適用する。common の学びへの案と、worker の制限を超える案は人に渡す

### Codex

- **K11: Codex は実機で確かめてから決めた。** Codex は直前（`pre`）とファイルの書き換えの直前（`path`）だけを扱い、失敗の直後は扱わない。PostToolUse に渡る結果は出力の文字列だけで、終了コードが無く、失敗を判定できないため。Codex の hook は Codex の sandbox の外で走る。hook は利用者が Codex の `/hooks` で信頼するまで動かない。Codex の開始時は、エージェントが AGENTS.md の指示で `show --on=session` を実行する
- Codex の hook は、cwd が Codex の場面の state か store と重なる（同じ・上・下）ときは注入しない。Codex の sandbox は cwd の下を書けるので、重なると重複の抑止、学びの本文、注入の記録を書き換えられるため。Claude の state と store は Claude の sandbox の外にあるので、この規則を当てない

### 計測と評価

- **K12: reads は開始時の読み込みだけを数える。**
- **K13: 受け取った側が、場面の良し悪しを返せる。** 注入するたびに、描画した学び 1 件ごとに、時刻・repo・id・場面の種類・当たった trigger・reader を 1 行記録する。開始時の注入では trigger を `session` か `untagged`（`on` が無い）とする。実際のコマンドやパスは書かない。評価は `agent-learnings feedback <id> <helpful|mistimed|wrong> --at=<kind>` で、直近 14 日に同じ repo・id・場面・reader の注入の記録があるときだけ受け付け、trigger は記録から写す。評価の reader は、環境変数の `CODEX_SANDBOX*`・`CLAUDECODE`・`AI_AGENT` の順で最初にあるもので決め（Claude Code の Bash も `AI_AGENT` を持つので `CLAUDECODE` を先に見る）、どれも無ければ人の評価として受け付ける。評価は、同じ組の注入の回数までしか数えない。`status` に場面ごとの注入の数、評価の数、見直しの候補（注入 3 回以上、`mistimed` と `wrong` が 2 件以上かつ注入の半分以上）を、`mistimed` と `wrong` の内訳、trigger ごとの回数、repo の key つきで出し、候補があれば開始時の知らせにも出す。記録は書き換えに強い形で残す（読む側で全項目を検査し直し、知らない値の行は `unknown` として数え、4MB を超えたら書かずに知らせる）。評価で学びを自動では書き換えない

## 却下した代替案

- **開始時の注入の量だけを増やす。** 学びは使う瞬間に文脈の奥へ沈んでいて、量を増やしても効く瞬間には届かない。
- **場面に正規表現や自由な文字列を許す。** 注入の経路と照合の壊れやすさが増える。LLM が付ける値を検査できなくなる。
- **評価を自由文で受ける。** 指標として数えられず、文脈へ戻すと注入の経路になる。
- **回転した記録（`.1`）も集計で読む。** 読むのは各記録の末尾 1MB に限る。回転の直後は直近の記録が見えず、受理と集計が一時的に小さくなるのを受け入れる。
- **頻出のコマンド（`git commit` など）への場面を禁じる。** 利用者が挙げた代表の場面そのものを禁じることになる。
- **場面の注入の git だけでなく、すべての git の起動で global 設定を読まない。** store の commit は global 設定の author を使う。
- **Codex の失敗の直後を、出力の文字列から推測する。** 確実に判定できない。

## Consequences

### 受け入れたリスク

- **R1: 注入面が広がる。** 学びは、指示として最も効きやすい瞬間（コマンドの直前）に入る。transcript から抽出された学び（ADR-0032 の受け入れたリスク）もそこに入る。LLM は狭い場面を付けられ、人が付けた広い場面を狭く上書きでき、一括の付け替えは事前の審査を経ない。念のための防御は、注意書き、再検査、URL を流さないこと、量の上限、付け替えの記録である。
- **R3・R12: タグの付け間違いと、付かない学び。** 開始時から外れた学びは「他に N 件」の行と `show` で読める。導入の時点で repo の学び 108 件に付けたのは 24 件で、dotfiles と kanbun-annotation の開始時は 8KB に収まらないまま残った（付けなかった学びの多くは、方針や進め方で場面に結びつかない）。
- **R8: 記録と評価は指標で、監査ではない。** エージェントは評価の reader を決める環境変数を偽れる。人の評価（reader が分からない）は reader を問わずに受理するので、Codex が環境変数を外せば Claude への注入の記録で受理される。Codex は自分の評価の記録を書き換えられる。Codex のエージェントが Codex への注入の記録を偽造できないのは、hook が sandbox の外で走り、注入の記録の置き場が Codex の書き込みの範囲に無いからである。Codex のエージェントは repo の設定で repo の key を選べるので、別の repo の学びを自分の文脈に出させられる（Codex は store を読めるので、読める範囲は広がらない）。
- 配備から 14 日は、reader の無い古い注入の記録も評価の受理の根拠になり、Codex の評価が Claude の古い記録で受理されうる。
- Codex の hook の信頼は、script の中身には結びつかない（codex-cli 0.163.0 で、中身を変えても発火した。command の文字列を変えたときに信頼が外れるかは確かめていない）。script の置き場は Codex の sandbox から書けない。信頼が外れると、場面だけの学びは Codex に届かなくなる。
- Codex の開始時に読んだ学びと、Codex の失敗の直後は、記録も評価もできない。注入の集計は Claude と Codex の合算で、Codex に失敗の直後が無いぶん比率が Claude と違う。
- Codex だけを 7 日以上使う環境では、Codex の場面の state の掃除が走らない（掃除は Claude の開始時に行う）。

### 拡張点

- 直前と失敗の直後を分けたくなったら、文法に修飾を足す（例 `cmd:git push@fail`）。
- Read、Bash による書き換え、Agent の呼び出しなどの場面は、文法に種別を足す形で拡張できる。
- 受動の評価（worker が会話から、注入した学びが使われたかを判定する）は作っていない。
- Codex の失敗の直後は、hook に終了コードが渡るようになったら足せる。
- reader ごとの集計に移るときは、reader の無い古い記録を「不明」として扱う。
- 記録の行に項目や場面の種類を足すときは、読む側を先に配る（ADR-0032 の版の規則と同じ）。
