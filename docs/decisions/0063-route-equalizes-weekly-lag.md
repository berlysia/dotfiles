# ADR-0063: route が週枠の遅れを provider 間で揃える

## Status

accepted (2026-10-30)

## Context

2026-10-30、利用者は週枠の扱いについて次の方針を示した。

> 「週間制限に対しては遅れを揃える視点で動くことにしよう。
> もちろん性能と結果が伴う範囲でということになるが。
> 5時間制限は単に待てば良いのであまり気にしない。
> 目標線を越えようとしなくていい。」

利用者は、記録のない委譲先で失敗した後に実績のある次点へ渡すよう求めた。

> 「記録で劣るものだけ外します。
> 実績のない移譲先に回した場合、失敗した後のフォールバックには実績のある次点を回すにしてください。
> 常時Sonnetに戻ってくると本末転倒です。」

利用者は、週枠の値を取得できない状態と週枠が無い状態を区別するよう求めた。

> 「週の枠があるけど取れてないものと、週の枠がないものは区別をしてほしい。
> 比較から外すをベースにして考えて。」

従来の route は週枠の状態や週枠の余りを条件に推奨先を切り替えていた。
週枠の遅れを provider 間で比べるには、週の経過率と使用率の差で順位を付ける必要がある。

## Decision

この ADR は ADR-0057 K3 の週枠の余りを使う候補行と、ADR-0062 K6 の余りによる推奨を上書きする。
両 ADR の本文は変更しない。

- **K1: 規則 2 を週枠の遅れ比較に置き換える。**
  規則 0（無料モデル）と規則 1（記録で明らかに高い採用率を示す委譲先）は先に判定する。
  両方で決まらないとき、従来の規則 2、週枠の余りの規則、規則 3 の sonnet 推奨に代えて、K2〜K4 の遅れ順を使う。
  候補が無い場合は K8 を適用する。
- **K2: 週枠の遅れを経過率から使用率を引いた値とする。**
  遅れ（pt）は `週の経過率 − 使用率` で求める。
  週の経過率は `100 × (週の長さ − リセットまでの残り時間) ÷ 週の長さ` とする。
  計算には従来の「+1 日」の目安を使わず、週の枠の `usedPercent`、`resetsAt`、週の長さを使う。
  実装の `RouteInput.paces` は provider 単位であり、Codex の Luna max と Terra は同じ `weeklyLag` を使う。
  使用率が目安を下回る provider も、他より遅れていれば候補にできる。
  週枠の数値が取れない場合と週枠が無い場合は、遅れを比較しない。
- **K3: 記録と枠の状態で候補を絞る。**
  sonnet と委譲先の記録が kind×size ごとに 5 件以上あり、委譲先の採用率が sonnet より 15pt 以上低ければ、その委譲先を外す。
  sonnet の記録が 5 件未満なら、採用率を理由に候補を外さない。
  委譲先の lapse が 30% を超える場合、その委譲先を「実績なし」として扱い、採用率が低い候補とは判定しない。
  5h が under でない provider、週が exhausted の provider、週枠があるが値を取得できない provider、週枠が無い provider は遅れの比較から外す。
  `週 unknown` と `週の枠なし` は異なる理由として出力する。
- **K4: 最大の遅れから 5pt 以内を同点の組にする。**
  候補の遅れの最大値を L とし、遅れが `L − LAG_TIE_POINTS` 以上の候補を同点の組とする。
  実装の `LAG_TIE_POINTS` は 5 である。
  同点の組では外部委譲先を `externalOrder` 順に並べ、sonnet を最後にする。
  組の外は遅れの降順にし、同じ遅れなら `externalOrder` 順に並べ、sonnet は外部の後に置く。
  順位は丸める前の値で決め、出力だけ整数 pt に丸める。
- **K5: 実績のない推奨に失敗時の次点を付ける。**
  kind×size の記録が 5 件未満か lapse が 30% を超える委譲先を推奨したときは、`失敗時:` 行を出す。
  対象は規則 2 の推奨と、規則 0 で記録が 5 件未満の無料モデルを推奨した場合である。
  次点には残りの候補から記録のある外部委譲先を遅れ順に選び、該当する外部が無ければ sonnet を選ぶ。
  sonnet も候補に残らない場合は K8 に従う。
  `route --exclude` は provider 名または委譲先名を複数受け取り、該当する委譲先を規則 0、規則 1、規則 2、試す候補から外す。
  provider 名には `codex`、`opencode`、`sarashina` を指定でき、委譲先名も指定できる。
  `claude`、未知の名前、空の値、値が無い指定はエラーにし、推奨を出さない。
  失敗の定義と失敗後の再委譲手順は `home/dot_claude/rules/model-offloading.md` に記す。
- **K6: 週枠の余りを使う規則と候補行を削除する。**
  週枠の余りを理由に推奨先を選ぶ規則、余りを独立して示す `試す候補:` 行、既存の `試す候補:` 行に付ける余りの注記を削除する。
  記録が少ない委譲先を示す `試す候補:` 行は残す。
  `RouteInput.surplus` と `surplusPoints` の利用も削除する。
- **K7: 推奨行に遅れと除外理由を出す。**
  1 行目の `delegation route v1` は維持する。
  規則 2 の `推奨:` 行には provider ごとの遅れを整数 pt で示し、正の値を遅れ、負の値を先行として表す。
  除外理由は次の行に示し、枠の理由は provider に、記録の理由は委譲先に付ける。
- **K8: 候補なしの処置。**
  規則 2 の候補を一つも使えず、Claude の 5h が ahead・exhausted、または週 exhausted の場合に `待機` を推奨する。
  5h だけが理由なら 5h のリセット時刻を出す。
  週だけが理由なら週のリセット日時を出す。
  両方が理由なら取得できた時刻のうち遅いほうを出す。
  理由となる窓の時刻が無いか過去なら `時刻不明` とする。
  Claude が unknown だけを理由に候補から外れた場合は sonnet を推奨する。
  `待機` のときは `試す候補:` 行を出さず、route の終了コードは 0 とする。

## 却下した代替案

- **差分最小案:** 従来の規則 2 の 1 周目・2 周目と週枠の余りの規則を残し、遅れを表示に加える。
  OpenCode は週枠 ahead では選ばれない。
  Claude の週枠が under の場合、余り 25pt を境に推奨が切り替わる。
  遅れは表示されても選び方は週枠の状態によるままであり、遅れを揃える方針を実現しない。
- **白紙設計案:** provider ごとの消費速度と 1 回あたりの消費量から、リセット時点で予測される最大のずれを最小にする委譲先を選ぶ。
  Codex と OpenCode の消費速度は取得できず、委譲 1 回あたりの消費量も記録していない。
  この案を実現するには時系列の使用量を保存するところから始める必要があり、ADR-0057 が示した常駐取得と並行 session の混在も扱う必要がある。
- **規則 3 を常に sonnet にする案:** sonnet の 5h 枠が埋まっていても sonnet を推奨し、利用者の「待つ」という方針に合わないため採らない。
- **候補を 2 つずつの差で比べる案:** 2 つの候補の差が 5pt 以内なら外部を先にし、超えたら遅れの大きいほうを先にする比べ方では、順位の循環が起こりうる。
  外部 A が 0pt、外部 B が +4pt、sonnet が +8pt の場合を考える。
  A と B は差が 5pt 以内なので、`externalOrder` で A が先になる。
  B と sonnet は差が 4pt なので、外部の B が先になる。
  A と sonnet は差が 8pt なので、遅れの大きい sonnet が先になる。
  A、B、sonnet の順位が一つに決まらないため、この案を採らない。
  K4 は最大の遅れからの幅で同点の組を作るので、循環しない。

## Consequences

- **R1:** 実績のない委譲先を繰り返し推奨すると、失敗を招くことがある。
  `失敗時:` 行には記録のある外部委譲先を優先する。
  sonnet と委譲先の記録が各 5 件以上あり、採用率が sonnet より 15pt 以上低い場合、その委譲先を候補から外す。
- **R2:** 週枠の使用率は整数で記録されるため、1pt 程度の差でも推奨先は入れ替わることがある。
  5pt の同点幅で小さな差による入れ替わりを抑え、実際の出力を観察して幅を見直す。
- **R3:** リセット直前の provider が推奨されやすくなる。
  これは週枠の使い残しを減らす方針に沿う動きであり、5h が under でなくなった provider は候補から外れる。
- **R4:** 規則の入れ替えで route テストの期待値が約 40 件変わる。
  実装では新しい規則ごとに期待値を更新している。
- **R5:** 委譲 1 回あたりの消費量を順位に反映しないため、重い委譲先でも次の route 呼び出しまで同じ順位に残る場合がある。
  消費速度と 1 回あたりの消費量を使う予測は、使用実績を集めてから検討する。
- **R6:** `待機` の推奨を受けるとメインループは委譲しない。
  Claude の 5h が 90% 以上ならメインループ自身も近く枠に達するため、route はリセット時刻を示し、利用者が待つか処理を続けるか決める。
- 同点の幅 5pt と `--exclude` で受け付ける名前は仮の決定であり、実際の route 出力を観察した後に見直す。
- `home/dot_claude/rules/model-offloading.md` が、`待機` 時の伝達と失敗後に 1 回だけ再委譲する手順を説明する。
