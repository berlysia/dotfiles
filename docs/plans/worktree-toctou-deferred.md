# worktree の置き場で、確認と操作の間に差し替えられる窓（見送った分）

worktree の置き場を `~/worktrees/<repo>/` へ移したとき、symlink とパスの確認から副作用までの間に、置き場を symlink に差し替えられる窓が残った。
直した窓は記録しない。
ここには見送った窓だけを書く。
実害が出たら、その時点で判断し直す。

## 前提

- 差し替えられるのは、同じ uid のプロセス（利用者自身のプロセスか agent VM）だけである。この repo に差し替える処理は無い。
- そのプロセスは、競合を使わなくても同じ削除や書き込みを直接できる。plan の「信頼境界」で、同じ uid の並行プロセスは防御の範囲外とした。
- シェル（bash 4）には `O_NOFOLLOW` と `fstat` に相当する操作が無く、Node と bash には `openat` が無い。検査を足しても窓は閉じ切れない。
- 3 条件は、1 が「戻せない・気づけない」、2 が「深刻度が高い」、3 が「通常の使い方で頻繁に起きる」である。

| C 印の読み取り → 再確認            | 終了コードと案内文が一時的に誤る                        | 不成立 / 不成立 / 不成立 | 不成立 / 不成立 / 不成立        |

- 確率は、どの窓も自分と Codex の両方が通常の使い方で 1 万回に 1 回未満と見積もった。根拠は、差し替える処理が無く、窓が数 ms の 1 手順分しかないことである。実測ではない。
- D・F・H・T4 の残りは、Codex が「直す」と判定し、判断が割れた。2026-10-30、利用者が plan の承認と T4 の質問で見送りを選んだ。
- T4 の残りの窓は、移す前の置き場の cleanup にも同じ形であり、この移行で増えたものではない。

## 直す場合の案

- D: `rm` をやめ、印のパスと「中身を確かめて `rm`」の案内を出して失敗する。
- F: 起動の後に VM の mount の一覧と host の実パスを照らし合わせ、違えば machine を止める。
- H（G も同じ）: 印の確保の後に、`~/worktrees` と `<repo>/` が symlink でなく、実パスが期待どおりかを確かめ直す。窓は狭まるが閉じ切れない。
- T4 の残り: 自動の再帰削除をやめるか、fd に基づく削除へ置き換える。
