# completion gate が時間切れにした後に残る子プロセス

## 今の形（2026-10-21 に観察）

- completion gate は `execSync` で `typecheck` と `test` を走らせ、120 秒で打ち切る。打ち切るとき `execSync` が止めるのは直接の子だけで、その子が起動した孫（`bun run test` の下の `node --test` や、テストが起動した `git`）は止まらない。Node 24.21.0 / bun 1.4.3 の環境で確かめたところ、孫が残った
- 残った孫は、gate が終わった後も CPU を使い続ける。次に走る check が、その分だけ重くなる
- 今の扱いは、時間切れの出力で知らせることだけ。時間切れのときの gate の文言は「実行を打ち切った。判定していない」「残っている test や git のプロセスと負荷を確かめて、1 回だけ走らせ直す。また時間切れなら利用者に報告する」「子プロセスが残りうる」と書く。残ったプロセスを止める仕組みはない
- gate の差し戻しは 3 回まで（`MAX_RETRIES = 3`）。時間切れが 3 回続くと、gate は判定しないまま通る。そのとき stderr に最大回数に達した旨が出るだけで、時間切れが続いたことは知らされない

## やりたいこと

時間切れの後に残る子プロセスを止める。プロセスグループごと止める（`execSync` ではなく、グループを作って走らせて打ち切る）案がある。

## 決めること

- 止める範囲: 打ち切った実行の子孫だけに限る方法（プロセスグループ）で足りるか。別の session が同時に走らせている check を巻き込まないか
- 時間切れが 3 回続いて判定しないまま通るとき、利用者に知らせる方法（今は stderr の一文だけ）
