# 英語を一語ずつ直訳した表現の残件

`.skills/ja-notation/SKILL.md` の「英語を一語ずつ直訳した表現」の節は、型の目印である。下の節がすべて片付いたら、このファイルを消す。

## 辞書の訳語で置いた名詞を拾う

承認（authorize）、要求（request）、事実（facts）、影響（impact）のように、英語の用語を辞書の訳語で置いた名詞は、今の節では目に留まらない。型として足す案は評価で効果が出ず見送った（経緯は節を足した commit の本文）。モデルはこれらを定着した言い方として扱う。

着手の条件: 上流 yomiyasu（nanaism/yomiyasu）が、同じ点検を次のマイナーで足すと予告している。取り込んだとき、上流の点検がこの層を拾うかを見る。拾わなければ、これらの名詞を ja-notation の名指しの直訳語の一覧（`references/translationese-words.json`。ADR-0045）に足すかを決める。一覧に足すのは利用者が名指しした語に限るので、どの語を足すかを利用者に確かめる。名指しする語の選び方を含むので、着手するときは Document Workflow（plan.md）を通す。

## 場所の名詞に推測で名前を付ける

「トークンを出す口」を、評価文に無い「エンドポイント」に直す動きが、節の有無にかかわらず出た。節は名前が書かれているときだけ置き換えると決めたが、出どころは yomiyasu の SKILL.md の「専門用語と名称の扱い」で、上流の規則は変えていない。上流を取り込むときに、この規則が推測を止める書き方になったかを見る。

## 文章スキルの「書き手」「読み手」を言い換える

「書き手」「読み手」のように「〜手」で人を表す言い回しは、日常の日本語ではまれである。一覧の項目「〜手（書き手・読み手）」が、これらを検出する。出力の欄の名前は「筆者に確かめたい点」に変えた。本文には、yomiyasu、koncise、ja-doc-profile、ja-notation などに約 350 行が残っている。

残っている行は、ファイルを編集すると hook が警告を出す。言い換える語は文脈で変わる（原文を書いた人なら「筆者」、文書を読む人なら「読者」、推敲を頼んだ人なら「依頼者」）。yomiyasu の本文は上流（nanaism/yomiyasu）から取り込んだものなので、上流との差分の扱いも決める。着手するときは、語の選び方と上流との関係を決めるので、Document Workflow（plan.md）を通す。
