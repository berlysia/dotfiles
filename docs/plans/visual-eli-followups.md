# visual-eli の作業から持ち越した課題

`eli5` を自作の `visual-eli` に置き換えた作業と、図の媒体を広げた作業が、範囲の外に回した課題である。
スキルの本文は `.skills/visual-eli/SKILL.md` にある。

## 1. 振る舞いの確認で残った取りこぼし

提案・未決。

- **内容**: 図の媒体を広げた後の確認で、3D の図が動かないことがあった。ほかに、規則が 1 か所ずつ守られなかった題材がある。本文を直すか、このままにするかを決める。
- **確認のしかた**: sonnet の subagent に本文を読ませ、日本語で説明させる。題材は、TCP の 3 ウェイハンドシェイク、`run_after_sync-skills.sh.tmpl`、`let` と `const` と `var` の違い、二分探索が範囲を絞る様子、2 つのベクトルの外積。期待する媒体は伝えない。HTML は Playwright で開き、コンソールのエラー、操作で図が変わること、ドラッグで向きが変わることを確かめる。
- **分かっていること**:
  - 3D の図（外積）が 3 回に 1 回、`TypeError: Cannot set properties of undefined (setting 'pos')` で止まり、3D の領域に何も描かれなかった。ラベル用の HTML 要素に、three.js のオブジェクトにしか無い `userData` を使っていた。動きのある SVG の図（二分探索）は動いた。頻度は 3 回のうち 1 回という数しか無い。
  - 止まったときの返答は、「ブラウザでの表示確認はこの環境ではできなかった」と書いていた。本文の自己確認の規則（ブラウザを操作する道具があれば `file://` で 1 回開く、サーバーは立てない）は、Playwright の MCP が `file://` を拒否するため働かない。`playwright-core` の `chromium.launch({ executablePath })` に検証用の Chrome のパスを渡せば `file://` を開けて、importmap の `integrity` による three.js のハッシュ検証（正しいハッシュは読み込まれ、替えた写しはブロックされる）も確かめられる。Windows 側の Chrome と Edge では、ハッシュの照合を確かめていない。
  - 規則が 1 か所ずつ守られなかった題材: TCP は、冒頭の文の括弧に説明の 1 文が丸ごと入った（規則は「数語」）。シェルスクリプトは `chezmoi apply` の 1 語に説明が無かった。二分探索は、返答が「16 個なら最大 4 回」と書いた（正しくは最悪 5 回）。
  - 「既存のファイルを上書きしない」規則は、同時に走る複数のエージェントの間では効かない。外積を並列で生成させると、3 つとも同じ名前に書き、最後の 1 つだけが残った。名前が空いているかを確かめてから書くまでの間に、ほかのエージェントも同じ名前を選ぶためである。順番に生成させると別の名前になる。
- **再開の入口**: 自己確認の規則を、この環境で働く形に直す（`file://` を開けない道具では、`127.0.0.1` に限ったサーバーを立ててよいとするか、ページのスクリプトを Node で読み込んで構文と参照の誤りを確かめるか）。three.js のラベルの置き方を、本文に短い雛形として書くことも候補である。並列で図を作らせる使い方をするなら、ファイルを作るときに、既にあれば失敗する書き方（シェルの `set -o noclobber` など）を本文に書く。

## 4. stop-describing-ui の適用で残った点

提案・未決。

- **内容**: HTML の図ページの、図以外の文言（見出し、キャプション行、注記、補助文、操作のラベル）に、外部スキル `stop-describing-ui` のチェックリストを通すようにしてある（`SKILL.md` の「Words outside the drawing」の項目）。効き方を確かめたのは各 1 回で、当たり切っていない文言もある。
- **確認のしかた**: 空のディレクトリで `claude -p 'visual-eli スキルを使って、二分探索が探す範囲を絞っていく様子を図解して。' --model sonnet --output-format stream-json --verbose` を実行し、スキルの読み込みをログの `Skill` の呼び出しで見る。3D の回帰は、題材を外積に替えて実行する。
- **分かっていること**: 見出し、入力のラベル、ボタンの文言は短くなり、キャプション行は手順ごとの複数文から、`/` で区切った見出し部と 1 文になった。図の中のラベルと凡例は残る。外積のページは、importmap のブロックが本文と一致し、読み込み失敗の注記は 3 点を保つ。
- **分かっていないこと**:
  - 毎回読み込まれるか。標本は 2 回である。
  - 文言の差が、チェックリストの効果か、実行ごとの揺れか。
  - キャプション行が短くなって、手順が追いにくくなっていないか。読んで判断していない。
  - Skill tool の無い場（subagent、agent-vm）での動き。本文は「読み込めなければ、当てずに書く」と定めたが、その場で試していない。
- **当たらなかった回に気づく手がかり**: 普段の利用では、読み込まれなかった回は出力に現れない。図ページの見出しが内容を説明している、キャプション行が 2 文以上の段落になっている、のどちらかが続けば、当たっていない。
- **再開の入口**: 当たらない回が続くなら、`SKILL.md` の「Words outside the drawing」の項目の書き方を直す。キャプション行が削られすぎるなら、同じ項目でキャプション行を対象から外す。上流を更新するときは、上流の差分を読んでから `home/dot_apm/apm.yml` の commit の値を替える（ほかの外部スキルは commit に固定していない）。
