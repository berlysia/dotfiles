`eli5` を自作の `visual-eli` に置き換えた作業と、図の媒体を広げた作業（どちらも 2026-10-08）が、範囲の外に回した課題である。
スキルの本文は `.skills/visual-eli/SKILL.md` にある。

## 1. 振る舞いの確認で残った取りこぼし

提案・未決。

- **内容**: 図の媒体を広げた後の確認で、3D の図が 1 回動かなかった。ほかに、規則が 1 か所ずつ守られなかった題材がある。本文を直すか、このままにするかを決める。
- **確認のしかた**: sonnet の subagent に本文を読ませ、5 題を日本語で説明させた。題材は、TCP の 3 ウェイハンドシェイク、`run_after_sync-skills.sh.tmpl` の 18-24 行、`let` と `const` と `var` の違い、二分探索が範囲を絞る様子、2 つのベクトルの外積である。期待する媒体は伝えていない。本文を 2 回直し、そのたびに 5 題すべてをやり直した（計画で決めた上限）。HTML は Playwright で開き、コンソールのエラー、操作で図が変わること、ドラッグで向きが変わることを確かめた。
- **分かっていること**:
  - 媒体の選び方は、3 回とも 5 題すべてが本文の表のとおりだった。TCP は `sequenceDiagram`、シェルスクリプトは `flowchart`、`let` などは表、二分探索は進める操作つきの HTML、外積は three.js の HTML である。
  - HTML の 6 ページのうち 5 ページは、エラーなく動いた。通信先は版を固定した `cdn.jsdelivr.net` だけで、ファイルは `.tmp/visual-eli/` の下に、既存のものを上書きせずに書かれた。
  - 3 回目の外積のページ（`cross-product-3.html`）は、`TypeError: Cannot set properties of undefined (setting 'pos')` で止まり、3D の領域に何も描かれなかった。ラベル用の HTML 要素に、three.js のオブジェクトにしか無い `userData` を使っていた。同じ題材の 1 回目と 2 回目は動いた。
  - そのときの返答は、「ブラウザでの表示確認はこの環境ではできなかった」と書いていた。
  - 本文の自己確認の規則（ブラウザを操作する道具があれば `file://` で 1 回開く、サーバーは立てない）は、この環境の Playwright では働かない。Playwright が `file://` を拒否するためである。私の確認では、`127.0.0.1` に限った `http.server` を立てて開いた。
  - 1 回目は、Mermaid の 2 題で、図の前に 2 文目が入った。`sequenceDiagram` のラベルに付けた引用符が、そのまま表示される形になっていた。冒頭を「ちょうど 1 文」とし、引用符の規則を図の種類ごとに分けて解消した。
  - 2 回目は、例のコードや末尾の段で、道具の名前や基本語に説明が無かった。用語の規則が返答の全体に当たると書いて、ほぼ解消した。
  - 3 回目に残った点: TCP は、冒頭の文の括弧に説明の 1 文が丸ごと入った（規則は「数語」）。シェルスクリプトは `chezmoi apply` の 1 語に説明が無かった。二分探索は、返答が「16 個なら最大 4 回」と書いた（正しくは最悪 5 回）。
  - three.js をハッシュで検証する形にした後（importmap の `integrity`）、外積を 3 回生成させた。3 ページとも、2 つのハッシュが本文と同じ文字列で 1 回ずつ入り、図が描かれ、ドラッグで向きが変わった。標本は 3 件で、実際に使うときの写し間違いの割合の根拠にはならない。
  - この 3 ページと、ハッシュを 1 文字替えた写しは、検証用の Chrome 153（`~/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome`）を `playwright-core` から動かし、`file://` で開いて確かめた。サーバーは立てていない。この方法なら `file://` を開ける。本文の自己確認の規則が想定する「ブラウザを操作する道具」としては、Playwright の MCP ではなくこちらが働く。
  - 利用者が WSL の Chrome を 155.0.8059.39 に更新した後、その Chrome でも `file://` から確かめた。正しいハッシュのページは読み込まれ、ハッシュを替えた写しはブロックされ、対応表に無いアドオンは解決に失敗した。生成した外積のページ（`cross-product-6.html`）も描かれた。
  - Windows 側の Chrome と Edge では、ハッシュの照合を確かめていない（Chrome は Linux 側と同じ 155 である）。
  - 「既存のファイルを上書きしない」規則は、同時に走る複数のエージェントの間では効かなかった。外積の 3 回を並列で生成させると、3 つとも `cross-product-4.html` に書き、最後の 1 つだけが残った。名前が空いているかを確かめてから書くまでの間に、ほかのエージェントも同じ名前を選ぶためである。順番に生成させると、4、5、6 と別の名前になった。
- **分かっていないこと**: 3D の図が動かない頻度。3 回のうち 1 回という数しか無い。動きのある SVG の図（二分探索）は 3 回とも動いた。
- **再開の入口**: 自己確認の規則を、この環境で働く形に直す（`file://` を開けない道具では、`127.0.0.1` に限ったサーバーを立ててよいとするか、ページのスクリプトを Node で読み込んで構文と参照の誤りを確かめるか）。three.js のラベルの置き方を、本文に短い雛形として書くことも候補である。並列で図を作らせる使い方をするなら、ファイルを作るときに、既にあれば失敗する書き方（シェルの `set -o noclobber` など）を本文に書く。
