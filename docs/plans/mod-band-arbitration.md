# Mod の帯（AbovePrompt）の調停

`AbovePrompt` の帯は 1 インスタンスで、hook は木を描くか `next(e)` に渡すかのどちらかになる。描いた hook が `next(e)` を呼ばないと、その下にある Mod の帯は出ない。今この帯を使う Mod は `workflow-band` だけで、`last-message-time` はプロンプト下のヒント行（`PromptHint` の `tail`）に逃がしたので、まだ衝突していない。2 つ目の帯の Mod を作りたくなったら、次のどちらかを選ぶ。片付いたらこのファイルを消す。

## 案

- **重ねる規約**: 帯の Mod はすべて `next(e)` の結果を包み、自分の行と縦に並べる（`ui.render` の説明は「return it, wrap it, draw your own」と包むことを認めている）。コードは各 Mod に数行だけで済む。ただし、全員が守らないと成り立たない。`maxRows` の取り分や、並ぶ順は決められない
- **調停役の Mod**: 帯を 1 つの Mod が持ち、ほかの Mod は行を差し出すだけにする。差し出し方は `$.state` か、`engine.create` で `$` に足す名詞（`dependencies` で型を共有する）にする。優先度、`maxRows` の配分、`hasSurvey` のときに引くかどうかを 1 か所で決められる。帯の Mod はみな、この Mod に依存することになる

- **調停役がいれば寄せ、いなければ自分で描く**: 調停役は `engine.create` で `$` に名詞（例: `$.band`）を足す。各 Mod は `$.band` の有無で分岐する。ある時はイベントの hook で作った行データ（文字列と色・bold・dim）を `$.band.put` で渡し、自分の `ui.render` は `next(e)` に譲る。無い時は今と同じく自分で描く。`engine.create` の結果は名詞がすべて省略可能（`Partial<EngineInterface>`）なので、実行時の判定はできる。渡すものを木でなく行データにするのは、名詞の呼び出しがイベントとして環境の境界を越え、render の hook は書き込めないため。作る前に確かめること: (1) `dependencies` に調停役を書いた Mod が、調停役なしでも読み込めるか（書かないと `$.band` の型が付かない）、(2) 名詞のメソッドの引数に関数を渡せるか（渡せるなら木を返すコールバックで済む）

## 取れない案

各 Mod は普段どおり描くだけにし、上に置いた調停役がすべての Mod の描画を集めて並べ直す形（Mod 側は調停役を知らない）は、今の API では作れない。調停役の `next(e)` は、最初に自分で答えた Mod の木だけを返し、その下の hook は走らない（`next.trace` も、自分で答えたリンクの手前で終わる）。`plugin.register` は拒否しかできず、tier を飛ばす `next.to` は managed の hook に限られる。調停役に近づけるとしても、各 Mod に「描くときも `next(e)` を呼んで含める」という決まりが 1 つ残る。

## 見直す条件

2 つ目の Mod が `AbovePrompt` に描こうとしたとき。重ねる規約で足りるか（順と行数を気にしないか）を先に確かめ、足りなければ調停役を作る。
