# 権限プロンプトでの merge で見送った欠陥

## 31 の後に PR の base が変わる

head が同じまま base だけ変わると、結果行のコマンドは新しい base へ merge する。`--match-head-commit` は head しか見ない。実害が出たら判断し直す。

自分の見立て:

- 最悪の場合: default branch 以外へ merge される。
- 条件: 31 からプロンプトの回答までの間に、PR の base を変える。
- 確率: 通常の使い方で 1 万回に 1 回未満。変えられるのは所有者の資格情報だけで、その短い間に変える理由が無い。

subagent（sonnet）の見立て:

- 最悪の場合: 想定外の branch に PR が merge される。
- 条件: wrapper の確認から承認までの間に base だけが変わる。
- 確率: 約 0.01% 未満。所有者が意図せず短い間に行う必要があり、第三者は資格情報を持たない。

3 条件の判断（両者とも該当なし）:

- 戻せない、または気づけない: 該当しない。PR は merged と表示され、revert で戻せる。
- 深刻度が高い: 該当しない。default branch は変わらない。
- 頻繁に起きる: 該当しない。base の変更は通常の操作に無い。
