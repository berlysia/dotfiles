# Codex への委譲の起動を道具にまとめる

Codex への委譲は、起動の作法をメインループが毎回守る形になっている。作法を忘れると、委譲が止まったり、成り立たない検証に時間を使ったりする。片付いたら、このファイルを消す。

## 状態

提案・未着手。出どころ: dotfiles-feedback 20261030T050238Z-b7e47eb725a4（#23）、20261030T043314Z-c787aa5482a3（#21）。

## 分かっていること

### stdin を待って止まる（#23）

- 2026-10-30 に、`codex exec` を read-only で background 起動した。出力は「Reading additional input from stdin...」の 1 行のまま、32 分進まなかった。標準入力を /dev/null にして起動し直すと、すぐに進んだ。
- 完了の通知は来ず、出力が増えないことを知らせる仕組みも無い。利用者に指摘されるまで、止まっていることに気づけなかった。
- reviewer の委譲は `reviewer-codex-run` を通る。この問題は起きなかった。reviewer 以外の委譲には、同じ役の道具が無い。`delegation` のサブコマンドで外部の委譲先を起動するのは、OpenCode 向けの `offload` だけである（2026-10-30 に `delegation --help` で確かめた）。
- 利用者の方針: 「呼び出し方の失敗を繰り返さないようにして。CLIにまとめるとかで対処できるので、努力ではなく道具で対応したい。」

### 全体テストを sandbox で流す（#21）

- 2026-10-30 に、route の実装を Codex（Luna、effort max、`workspace-write`）へ委譲した。brief ではテストファイルを 1 つ名指しした。
- Codex は名指しのテストが通った後、自分の判断で全体テストを sandbox の中で起動した。メインループはそこで委譲を止め、sandbox の外で全体テストを流した（47 秒、失敗 0）。
- `model-offloading.md` の Codex の節は、起動の引数を定めているが、テストの範囲を定めていない。OpenCode の節には「テストの実行はメインループが行う」とある。

## 未確認

- stdin で止まる回と止まらない回の違いは分かっていない。起動の経路で stdin の状態が違うと推測している。
- 止めたので、sandbox の中の全体テストがどれだけ落ちるかは観察していない。

## 再開するときの手順

1. `delegation` に Codex の委譲を起動するサブコマンドを足す。brief のファイル、書き込むかどうか、worktree を受ける。route の推奨からモデルと effort を取り、stdin を /dev/null にし、出力をファイルに書き、台帳の行を開いて閉じ、`-C` の基準を確かめる。
2. 出力が一定時間増えないときに知らせる。終了するか、警告の行を出すかは、作るときに決める。
3. brief の末尾に「名指ししたテストだけを流し、全体テストと typecheck は流さない」を自動で足す。メインループが sandbox の外で流す。
4. `model-offloading.md` を、生の `codex exec` を打たずにこの入口を使う書き方へ直す。生の起動を guard で拒否するかは、別に判断する。

Codex に渡す実装の前提は、`docs/plans/document-workflow-gate-feedback.md` の「テストを走らせる実装を Codex に渡す前提」にもある。
