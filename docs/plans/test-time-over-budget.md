# テストの実行時間を、code-quality.md の目標と上限に収める

## 今の形（2026-10-27 に手元で計測）

master の `06a6d373` で、各テストを 1 回ずつ計測した。
ほかの作業も動いていて、load average は 0.9 から 3.6 だった。

| 対象                                           | 計測値           | 目標  | 上限  |
| ---------------------------------------------- | ---------------- | ----- | ----- |
| 単体テストの全件（5536 件）                    | 39.5 秒、37.2 秒 | 10 秒 | 1 分  |
| perf（172 件）                                 | 23.1 秒          | 1 分  | 2 分  |
| heavy（479 件）                                | 93.2 秒          | 1 分  | 2 分  |
| hook のファイルを含まない commit の pre-commit | 0.74 秒          | 3 秒  | 10 秒 |
| hook のファイルを含む commit の pre-commit     | 38.3 秒          | 3 秒  | 10 秒 |
| pre-push                                       | 1.94 秒          | 15 秒 | 30 秒 |

上限を超えているのは、hook のファイルを含む commit の pre-commit だけである。
`scripts/hooks/pre-commit` は、`*claude/hooks/*` のファイルが stage にあると `bun run test` で単体テストを全件実行する。
そのため、時間は単体テストの全件とほぼ同じになる。

単体テストの全件の時間は、遅いファイルでほぼ決まる。
`node --test` は、ファイル同士を並列に実行し、ファイルの中のテストを順に実行するためである。

- `tests/formal-check.test.mjs` は、単独で 25.1 秒かかった。プロセスを起動するテストが、1 件あたり 1.3 秒から 2.5 秒かかる。時間切れを確かめるテストは、1 件あたり 1.5 秒かかる
- `home/dot_claude/hooks/tests/unit/japanese-check.test.ts` は、単独で 12.2 秒かかった。どこに時間がかかるかは調べていない

heavy では、`home/dot_claude/hooks/tests/heavy/completion-gate.test.ts:154` が 1 回失敗した。
pid が 1000 ms 以内にファイルへ書かれず、そのときの load average は 3.64 だった。
同じファイルを単独で実行し直すと、10 件すべて通った。
負荷が高いと失敗するのではないかと推測しているが、原因は確かめていない。

## やりたいこと

1. pre-commit で単体テストを全件実行するのをやめ、変えたファイルに関係するテストだけを実行する。全件は pre-push か CI で実行する。単体テストを速くしても 3 秒以内には収まらないので、これを最初に行う
2. 1 ファイルで 3 秒を超える単体テストを、複数のファイルに分けて並列に実行させる。プロセスを起動するテストは、エントリポイントを確かめる 1 件だけを残し、ほかは関数の呼び出しに替える。時間切れのテストは、時間を短く渡せるようにする
3. `completion-gate.test.ts` の pid の待ち方を、条件がそろうまで期限つきで待つ形に替える

## 決めること

- 変えたファイルとテストの対応をどう求めるか。`docs/plans/heavy-tests-pre-push-by-path.md` と同じく、テストのファイルに、そのテストが対象にするパスを書く方法がある
- pre-push を 15 秒に収めたまま、単体テストの全件をそこで実行できるか。全件が 10 秒に縮むまでは、CI に任せるか
