## 事実

- `MAX_ENTRIES = 40`（`home/dot_claude/hooks/lib/agent-learnings/core/ops.ts:21`）。超えた分は `evictEntries` が seen の少ない順・updated の古い順・位置の早い順に消す。add・セッション末の worker・promote が同じ規則を使う
- ADR-0032 の 53 行目が上限と追い出しを決めている。上限の理由は grep した範囲では書かれていない
- 消した id は、store の git の commit 本文に `evicted: …` か `evict …: over the entry cap` として残る
- 消した学びの中身は `git show <commit>^:<file>` で取り出せる
- 日常的に起きている。2026-10-29 00:59 のセッション末の worker が L-935a16a49c4f・L-d8f401b2205a・L-425c48d9977d を押し出した。過去にも 4 件・1 件・1 件の押し出しの記録がある
- ADR-0042 で注入は開始時の一括から場面ごとに変わり、開始時の 8KB の切り詰めが件数の上限と結びつく理由は弱くなった（未検証の推論）

## 決めること（ADR が要る）

- 上限を外す / 上げる / 押し出す代わりに別ファイルへ退避する / 押し出しを利用者に知らせる
- 上限が質の低い自動抽出の歯止めとして働いているかを、押し出された項目の seen と中身から確かめる

## 棚卸しのときの扱い
