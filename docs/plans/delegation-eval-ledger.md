# 委譲先のモデル・effort 別の評価を記録する

利用者の提案（2026-10-28）: オフロードが増えるので、モデルとエフォート別の評価をメインループが記録していく。あわせて、レビュアーに指摘の Tier を判別させる。

## やること

- レビュアーの brief に、指摘ごとの Tier（must / should / nit）を付けさせる。must が無くなったら周回を止める（workflow.md の「全員 pass で軽微指摘のみ」と接続）
- 委譲 1 回ごとに 1 行を追記する台帳（JSONL）と、集計を出す CLI を作る
  - 識別: 日付、モデル ID（正確な版）、effort、仕事の種類、規模
  - 識別に加えて、ハーネスを版つきで書く。例は Codex CLI、Claude Code の Agent、OpenCode、Cursor である
  - ハーネスの起動の仕方も書く。sandbox の種類、--auto などの権限、渡した指示ファイルである
  - ハーネスを分けて持つのは、同じモデルでもハーネスの組み込み指示や権限の初期値で結果が変わるためである
  - 例: Codex の出力に毎回付いた「japanese-check 未検証」の断り書きは、Codex が読む AGENTS.md か、配布したスキルの指示から来ている可能性がある。モデルの性質かどうかは未確認
  - 測れる値: 形の誤り、やり直し件数、Tier 別の指摘数、triage で除外した数、後で別の主体が見つけた欠陥とその主体、使った枠・時間
  - 印象: 別欄。標本数を添える
- 委譲先の表の改訂を、集計がたまってから根拠つきで行う。仕事の種類別の集計は、`delegation route` が kind×size の組ごとの行で出すようになった
  - effort の改訂は、`delegation review` の「effort の見直しの条件に当たる」の行が出てから始める（ADR-0064）
  - 委譲先の表のほかの列（探索・定型実装・ドキュメント、軽量スイープ、高難度の委譲）を改訂するかは決めていない
