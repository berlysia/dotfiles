# スキルの読み込み・発火を計測するツールの計画

今後、セッションの transcript を解析する CLI またはスクリプトを作る。スキルの保守担当者が、導入・参照文の変更後と、期待した動作がなかったときに使い、宣言と実際の読み込みの差を確認する。この文書は将来の作業を記すもので、ツールは未実装である。

## 計測するもの

- スキルごとの読み込み回数と、読み込んだセッション数。Read の対象パスと成功した結果、スキル本文の展開記録を根拠にする。
- スキルごとの発火回数と、発火したセッション数。Skill の呼び出しを読み込みとは別に集計し、通常の依頼からの参照と明示起動を区別する。`-p` 内の展開など、Skill 呼び出しが残らない経路も別に示す。
- 期待するスキルを定めた試行ごとの、読み込み・発火の有無。一般語として名前を使った負例も用意し、誤発火を確認する。宣言された参照先と実際の読み込み先を比較する。

transcript の構造を解析し、呼び出しは `type: "tool_use"` のブロックから抽出する。ツール一覧、grep の出力、引用、モデルの「読んだ」という自己申告は実績に含めない。結果には根拠となる記録の位置を付け、記録がない場合は未観測と示す。

## 利用時の確認と限界

保守担当者は、通常依頼から本文の参照までの経路、明示起動のみの制約、hook のモデル向け通知と人向け通知の区別を確認する。観察用の権限が実行を妨げた試行は、スキルが効かなかった試行と分ける。比較用のコピーは本物と挙動が違う場合があるため、変更後は配布された本物でも確認する。

読み込みや発火は規則の遵守を証明しない。読み込む量が多ければ守られなくなることを前提に、出力形式の規則が実際に参照される箇所にあるか、期待する出力になったかは別に検証する。単発の成功から常に効くとは判断せず、試行数と条件を示す。機械で判定できる確認はツールへ移し、人が判断する確認と分ける。
